Design document · Draft 2

GeoMotion — the next‑generation map editor

Not an evolution of the generator we shipped — a professional editing instrument in the lineage of Resolve and Figma, purpose-built for map storytelling. Draft 2 rebuilds the design around five ideas: an editing philosophy that governs every feature, a true scene graph, smart objects as the single source of truth for places, a geometry editor no motion tool has, and one procedural substrate wearing three skins.

§00

Lessons from v1

We shipped a working v1 — data in, narrated MP4 out, editable in between. Its value to this document is the scar tissue. Six lessons anchor every position below:

The monolith layer

Was: one "regions" layer with ~40 fused fields. Now: a scene graph of small nodes; the tour decomposes into a camera rig plus a scene sequence.

The time-source bug

Was: a stray map event re-rendered export frames at the wrong t. Principle: one deterministic clock; every evaluator is a pure function of (document, t).

The frozen voice bed

Was: narration mixed once; any retime broke sync forever. Now: audio clips are scene children; the mix renders from clips at export. Ripple works both ways.

LLMs typed the numbers

Was: the model wrote figures literally and once spoke "{previous}" aloud. Principle: facts belong to smart objects (§05); models write words around references; everything AI emits is validated.

The join was fragile

Was: datasets joined to geometry by name-matching, per project, with alias tables. Now: joins happen once, into entities with stable IDs. The whole bug class dies.

WYSIWYG or nothing

Right, kept: preview renders at output resolution; one render path for screen and export. There is never a second backend to drift.

§01

Product vision

GeoMotion is the editor where the world is the scene graph and every place is an object that knows itself. In After Effects a map is pixels; in GeoLayers it is a plugin inside a host built for something else; in Flourish it is a template with a ceiling. In GeoMotion, West Bengal is a first-class object — with geometry you can edit, facts it carries (population, capital, election result, flag), animations you can drop onto it, and a camera that can be told to look at it. Labels, callouts, charts, narration, and thumbnails all bind to that one object. Change the object; everything downstream follows.

The problem: the people best at explaining the world spend most of their week on tooling — QGIS → Illustrator → AE + GeoLayers → Premiere, re-importing at every seam, joining data by hand, timing narration by eye. One border revision means redoing four stages. GeoMotion is one document where geometry, data, animation, cameras, and voice stay live together.

Four commitments define the product:

  • Everything stays editable. No bake step, no "generated then flattened." An AI-drafted camera move is keyframes you drag. A one-click preset is a behavior stack you can open.
  • Places are objects, not pixels — smart objects (§05) are the single source of truth every layer binds to.
  • The voice drives the clock. Narration is measured and the picture is cut to it — an engine primitive, not editor craft.
  • Progressive depth. Drag-drop preset → editable stack → full node graph (§06). Beginners never see the graph; experts never hit a ceiling. Flourish's first minute, without Flourish's wall.

§02

Editing philosophy

Resolve is not a feature list; it is an editing grammar. These principles are normative — every future feature is reviewed against them, and a feature that violates one needs a written excuse.

One click (or one gesture)

  • Double-click any region → the camera frames it (the framing solver, §09). This is the signature gesture of the whole product.
  • Drop a preset on a layer → it animates. Drop a dataset column on a property → it binds. Drop a voice line on a scene → it times.
  • Solo / mute / lock a layer; switch 16:9 ↔ 9:16; play from here; add a keyframe at the playhead.

Never a dialog

  • Color, scale, and easing edit in popovers on the canvas or timeline, live-previewing while open. Style never goes modal.
  • Region assignment, binding retargets, and preset parameters edit inline in the inspector.
  • Dialogs are reserved for genuinely destructive or file-system acts: deleting an asset in use, importing from disk. Export of a draft is one click with defaults; the full deliver page (§14) is a workspace, not a dialog.

Always draggable

  • Every number scrubs. Every keyframe and handle drags. Camera paths drag on the map itself.
  • Layer bars trim and slide; story blocks ripple; scene thumbnails reorder like slides.
  • Assets drag from the browser onto canvas, layers, or properties — a flag onto a callout, a column onto a fill.

Always on the keyboard

  • Space / JKL transport · V select · H pan world · P pen (§08) · C camera
  • ⌘K command palette reaching every command, node, entity, and dataset column · U reveals animated properties (AE's best idea) · [ ] trim · ⌘D duplicate · F frame selection

Latency budgets are features

Drag feedback < 16 ms; click acknowledgement < 100 ms; seek-and-show < 250 ms at proxy resolution. A budget miss is a bug, triaged like one. The document is never invisible behind a mode; AI actions are ordinary undoable edits; autosave is always on.

§04

Scene graph

A real scene graph, the way cinema software means it: content lives in a world; cameras observe it, they don't contain it. Every node inherits transforms from its parent; every node declares its space — world (geographic: lng/lat/altitude) or screen (composition pixels), with camera-relative anchoring as a constraint for HUD-like elements.

Consequences that fall out of the shape: insets are just a nested map context; a second camera is a hard cut away (§09); a group of world-space layers pans with the planet while the UI group holds still; and "which camera is live" is itself an animatable track.

Decision 01 Logical tree, flat storage

The scene graph above is the logical model. Physically, nodes live in a flat Map<NodeId, Node> with parentId + fractional-index order — Figma's shape. Undo is an inverse-patch log; AI proposals are patch sets; multiplayer (§16) becomes a per-property CRDT problem instead of a tree-merge nightmare. v1's nested JSON — which deep-cloned the whole project per keystroke — is the rejected alternative.

Every property is a track

Node  { id, type, name, parentId, order, space: 'world'|'screen',
        props: Record<string, Track>, locked, hidden }

Track = { kind: 'static',    value }
      | { kind: 'keyframed', keys: Keyframe[] }
      | { kind: 'bound',     ref: EntityRef | DatasetRef, path, scale }   // §05
      | { kind: 'expr',      source, inputs }                             // §06

// value(t) = behaviors( expr( base(t) ) )  — one pipeline for the whole app

The inspector shows a source pip on every property — grey static, teal keyframed, violet bound, amber expression — and any property can be retargeted between kinds in place. Assets are content-addressed blobs (OPFS) referenced by hash; the project file is small, diffable, versioned JSON with per-version migrations (v1's importer is the first).

§05

Smart objects

The keystone of the product. A smart object is an entity with a stable ID — in-wb is West Bengal, forever — that owns three things:

  • Geometry, in versions. Official depiction, Natural Earth, historical snapshots by date, and any user-edited variant from the geometry editor (§08). A project sets a boundary policy; layers reference the entity, not a file.
  • Facts, with provenance. A typed table — population, capital, leader, GDP, election result, flag asset, article link — where every fact carries {value, source, asOf}. Imported datasets merge in as fact columns through one join, with loud diagnostics. Computed facts (rank, delta vs previous round) derive automatically.
  • Bindings out. Anything can reference {entity.capital}, {entity.population|compact}, {entity.rank} — labels, callout fields, chart series, narration lines, thumbnail text, legend domains.

This is v1's {value} placeholder system grown up: narration that says {entity.population} re-synthesises when the fact changes; a label cannot disagree with the callout because both read the same cell. It also finishes what the placeholder normaliser started — the AI copilot (§12) writes references, and the fact engine fills them, so narration structurally cannot contradict the map.

Provenance is not decoration: the credits line can be generated from the facts actually used in the video — a journalism feature no competitor has. A Wikidata/Wikipedia connector proposes facts; the user approves; the fact lands with source and date. Nothing is ever silently fetched into a document.

Decision 02 Entities are the join; layers never join data themselves

Datasets join once, into entity facts, at import — with unmatched-key diagnostics at that single choke point. Every layer, label, chart, and narration line then binds by entity ID. v1 joined by name inside the regions layer, and every dataset re-fought the same alias battles (DNHDD, "A & N Islands"…). That entire bug class collapses into one reviewed join per dataset.

§06

Motion engine — one substrate, three skins

Underneath, every animation is a procedural graph: typed nodes transforming geometry, paths, values, and pixels. Almost nobody should have to see that. The same substrate wears three skins, and you can drop down a level at any time without conversion:

  1. Preset — drag "Trace Border" from the library (§11) onto a region. Done. Internally it instantiated a graph.
  2. Stack — the inspector shows that preset as an ordered list of behaviors with parameters — reorder, retime, tweak, toggle. Apple Motion's great idea, kept linear.
  3. Graph — "Open as graph" reveals the full node editor for branching, merging, and custom wiring. Blender Geometry Nodes energy, strictly opt-in.
CapabilityDesign
Keyframes & curvesPer-channel bezier + hold + linear; graph editor as a timeline drawer; preset curves (v1's easing set, including the overshoot); roving keys for constant-speed paths.
Spatial pathsPosition keys form a draggable bezier in the layer's own space — world-space paths interpolate on the great circle, screen paths in pixels.
Parenting & constraintsTransform inheritance within a space; cross-space attachment (screen card following a world anchor) is a constraint resolved after projection.
Masks & mattesPath masks, alpha/luma mattes, and region masks by entity reference — satellite footage clipped inside a tracing border is one drop.
Blend modes, groups, componentsGPU blend passes; groups inherit transform/opacity; Figma-style components with typed overridable props (callout, legend, lower-third ship as the first masters).
ExpressionsA small deterministic, side-effect-free DSL (numbers, vectors, colors; time, property refs, entity facts; seeded noise). Deterministic because export correctness and multiplayer both demand identical results for identical (doc, t). Sandboxed JS rejected for that reason.
Bake anywhereAny preset, stack, or graph can bake to raw keyframes — one-way door, clearly labelled, for the "I just want to nudge this one frame" moments.
Decision 03 Graphs are the substrate, never the front door

Draft 1 rejected node-graph-first authoring (the Fusion problem) — that stands. What changed: the graph now officially exists underneath, as the common representation of presets and behavior stacks, exposed only on request. One implementation, progressive disclosure, no ceiling.

§07

Map system

The map is a context node, not a background: it defines projection, basemap, and terrain; world-space descendants project through it. Insets are nested contexts; projection is an animatable property.

ElementDesign
BoundariesEntity-referenced (§05): countries, states, districts, cities in multiple depictions and historical snapshots; PMTiles at scale; user edits become geometry versions (§08).
Region layersBind fills/strokes/opacity to entity facts through validated scales (lightness-monotonic, CVD-checked — v1's validator promoted to the scale editor). Legends are components bound to the same scale object; they cannot disagree with the map.
Animated borders & fillsStroke-draw on true topology (shared edges trace once — v1's dissolve, now engine-level); fills sweep from centroid, flood from a border, or stagger by rank. All presets in the library, all graphs underneath.
Points, routes, flowsGeodesic/arc routes with travelling markers and camera-follow (v1 parity); flow maps — OD arc bundles, width bound to volume, animated particles.
LabelsAn engine, not hand placement: deterministic collision solver, leader lines for small regions, per-label persistent overrides. Names come from entities — they are never typed twice.
Heatmaps / hexbinsGPU aggregation over point datasets.
Terrain & imageryDEM terrain with animatable exaggeration (flat map rising into relief is two keyframes); satellite/hybrid basemaps.
Projection changesVector layers morph between projections (d3-style interpolation); raster basemaps cannot reproject live, so they crossfade through the morph — an honest limitation, staged with craft.
Decision 04 MapLibre renders the ground; GeoMotion renders everything that moves

MapLibre keeps tiles, terrain, and projection math. Data layers, regions, labels, and all animation move into our compositor — v1 spent real effort fighting setPaintProperty caches and feature-state for per-frame animation, and that model caps out. Forking MapLibre (maintenance trap) and building tiles from scratch (five years of edge cases) both rejected.

§08

Geometry editor

The biggest gap in draft 1, and the feature no motion tool has ever shipped: creators should not need QGIS to fix a border. GeoMotion becomes QGIS-lite — the 20% of GIS editing this audience actually uses, native, non-destructive, and animatable the moment the edit lands.

The organising principle is topology first. Region geometry is stored as a planar arrangement — shared edges exist once, referenced by the regions on either side. Move the Bengal–Jharkhand border and both regions update; no slivers, no gaps, ever. (v1's border-dissolve already proved real datasets carry clean shared-edge structure; we make it the storage model rather than a render trick.)

ToolDesign
Pen PBezier drawing in world space — new regions, disputed lines, custom routes; closes into topology-aware polygons.
Vertex editingDrag vertices/edges with snapping to vertices, edges, graticule, and other layers; box-select vertex groups; shared edges edited once by construction.
Boolean opsUnion (merge districts), subtract, intersect, split-by-drawn-line — the "carve Telangana out of Andhra" workflow in four clicks.
Simplify & smoothTopology-preserving simplification (Visvalingam on the shared-edge arrangement) with a live vertex-count/fidelity slider; corner smoothing.
Offset / bufferInset & outset paths — coastline glows, territorial-waters bands, exclusion zones.
Disputed bordersEdge classification, not a hack: an edge marked disputed(claimants…) renders per the project's boundary policy — dashed, cased, or claimant-coloured. The Kashmir problem handled as data.
Non-destructiveEvery edit session produces a new geometry version on the entity (§05). The official depiction is never mutated; projects pin versions; history channels keep dated snapshots side by side.
Why this wins: the moment geometry editing lives beside animation, "edit the 1947 border, then animate it changing" is one tool and one afternoon. Today that is QGIS → export → re-import → re-style → re-animate, per revision. No competitor — not GeoLayers, not AE, not Flourish — can follow without becoming a GIS.

§09

Camera rigs

Cameras are nodes observing the scene (§04), and a camera's motion is a rig: an ordered stack of camera modifiers, evaluated top-down like §06 behaviors — because they are §06 behaviors, specialised to the camera. Each is toggleable, keyframable, and saveable; a named stack is a rig preset in the asset browser.

  • Look-at targets are entities — "look at West Bengal" survives a geometry edit, and the framing solver (v1's pure fitBounds math: padding, pitch compensation, small-region zoom clamp) turns the target into framing deterministically. AI and humans produce identical framings from identical inputs.
  • Moves: dolly (center path), zoom, tilt/pitch, orbit, roll (compositor-rotated — MapLibre has no roll; documented fake that reads correctly at explainer angles), bezier flight paths dragged directly on the map, altitude riding its own curve.
  • DOF is stylised tilt-shift (no depth buffer from MapLibre) — labelled stylised, shipped anyway; it is what the genre uses.
  • Multiple cameras + switcher track — election-night pattern: a camera per state, hard cuts on demand, the switcher itself editable on the timeline.
  • Double-click any region → flyTo is the philosophy §02 gesture, implemented as a one-block rig.

§10

Scenes, storytelling & timeline

The storytelling engine is structural, not a wizard. A project is a sequence of scenes; a scene is a composition — its own cameras, map context, layers, audio — that is also a reusable unit. Two views of the same structure:

  • Storyboard view — scenes as slide thumbnails: reorder by drag, duplicate, borrow a scene from another project, read the narration under each card. Presentation-software ergonomics over real compositions.
  • Timeline view — the full editor underneath: tracks, clips, keyframe rows, curves.

Inside scenes live story blocks — v1's beats, kept alive in the document: a time range owning a narration line (text + measured audio) and links to the nodes it choreographs. Dragging a block ripples its children and re-anchors what follows; re-recording a line re-measures and ripples. The frozen-bed bug is structurally impossible, in both directions.

FeatureDesign
TracksLanes for graphics, cameras, audio (voice/music/SFX), and the story track. Lanes are views — a node owns its timing; lanes organise.
Edit grammarRipple, roll, slip; range select; snapping to playhead, edges, block boundaries, audio transients; markers with notes; folders and colours.
AudioClips with cached waveform peaks, per-clip gain/fades, music ducking as an audio behavior keyed to voice clips, loudness meter targeting −14 LUFS.
NestingScenes nest as clips with exposed parameters — an "election lower-third" scene with a candidate-name param is a template.
Keyframe laneLayers expand to per-property rows inline; the curve editor is a drawer, not a modal elsewhere.
TransitionsTransition nodes spanning clips: crossfade, wipe, and the camera-bridge — outgoing camera hands off to the incoming through one interpolated move.

§12

AI copilot

One rule: AI writes patches, never pixels. Every copilot emits a DocumentPatch — the same typed transaction a human edit produces — shown as a reviewable proposal, then accepted, edited, or dismissed. Accepted output is indistinguishable from hand work because it is ordinary document content. Smart objects complete the safety story: models write entity references; the fact engine fills them; narration structurally cannot contradict the map (the v1 lesson, now architecture).

Decision 05 Copilots ride the plugin API

AI features consume the same typed, sandboxed document API as plugins and the console (§15). One capability model, one security review — and the community can ship copilots we didn't imagine. Keys stay server-side, exactly as v1's .env.local middleware does today.

§13

UX & panels

One window, one document, three workspaces — governed by §02. No modal Studio owning state the editor can't see (the v1 sin, corrected structurally):

  • Story — storyboard view, script and narration per scene, data and fact tables, AI proposals inline. Dataset-first onboarding: pick data → working draft in 60 seconds → every part of it editable.
  • Design — canvas centre; left rail tabs Layers / Assets / Data; right inspector with source pips on every property; V objects vs H world resolving the "move the map or the thing on it" ambiguity explicitly; geometry tools (§08) live here as a canvas mode, not an app.
  • Deliver — formats, render queue, publish targets, reframe review for 16:9→9:16 with per-layer safe-area pinning.

The timeline docks under all three. ⌘K reaches everything. The feel target is Figma: direct manipulation, 60 fps interaction, autosave, undo across everything including AI patches; dense-but-calm panels; AI as quiet buttons, never a takeover.

§15

Plugin SDK & marketplace

Not a plugin hook — an SDK. A plugin is a sandboxed worker with a typed capability API: read the document, propose transactions, register node types, behaviors, panels, data connectors, and copilots; fetch only declared origins; no DOM, no ambient network. CLI scaffold, hot-reload dev mode, publishable to a reviewed registry. The same API is the automation console and the AI copilots' toolset — one surface, three consumers, one security review.

Domain packs are the point — whole genres shipped without touching core:

Earthquakes (USGS feed)Flight radarWeather systemsHistorical bordersShip tracking (AIS)Trade flowsPopulation pyramidsMilitary units / ORBATWildfire perimeters

The marketplace sells packages: assets + components + presets + connectors + copilots bundled. The reference example — an Election Package: animated parliament arc, vote counter, result banner, swing arrows, choropleth presets, and a live-results connector. One click installs it into an org library; every piece opens into the stack view, because nothing in GeoMotion is a black box — including what you buy.

§16

Collaboration & cloud

This is where Figma won, and it is a first-class pillar, not a stretch goal. The flat store + patch model (§04) makes each step incremental:

  • Multiplayer — per-property CRDT merge, presence cursors and selections, follow-mode ("watch my screen").
  • Comments — anchored to a node and a time range: "this label, at 0:42." Resolve threads from the storyboard.
  • Version history — every change patch-logged; visual diffs render two frames side by side. "Who moved Kashmir's label" is answerable in one click.
  • Approval workflow — draft → review → approved; approved scenes lock (broadcast's non-negotiable); publishing requires approval in org projects.
  • Render cloud — the same deterministic engine on servers: queue 8K/ProRes/batch jobs from Deliver; the browser never blocks.
  • Live program-out — a headless viewer URL that OBS/vMix captures as a browser source, driven live from the editor. The election war room becomes: one person on cameras, one on the data feed, one editing tomorrow's graphics — in one project.
  • Living embeds — published interactive scenes re-render when their bound data updates; the video and the always-current web version are the same project.

Open source (MIT core) is the wedge: editor and engine free forever; revenue from cloud sync, collaboration, render farm, and the marketplace — the Figma/GitLab shape, aligned with creators.
